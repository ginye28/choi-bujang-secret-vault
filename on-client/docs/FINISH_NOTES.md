# 케셰브 마지막 총공세 기록

## 1일차 — 2026-10-26 11:00~11:02 KST

기록 대상은 22단계까지 작업하던 기존 워크벤치 프로젝트 폴더 `choi-vault`의 `on-client`입니다. 기존 프로젝트 폴더와 제출물은 그대로 둡니다. 아래에서 실제 모드와 설명용 예제 모드를 나누어 적습니다. 예제 데이터는 실제 조회 결과가 아닙니다.

### 실행 방법

`on-client` 폴더에서 PowerShell을 열고 실제 모드로 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Background
```

실제 모드 주소: `http://127.0.0.1:5189/`.

예제 화면을 볼 때는 같은 명령 끝에 `-Demo -Port 5190`을 붙여 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Background -Demo -Port 5190
```

예제 모드 주소: `http://127.0.0.1:5190/`. 화면 머리에 `예제 데이터(demo) · 실제 연결 아님`이 표시됩니다. 실제 화면의 `연결 없음`과 혼동하지 않습니다.

### 권장 제작 기간에 다듬을 핵심 기능 3가지

학생 모듈의 `createStudentView`에서 대응하는 함수 이름을 대조했습니다. 아래 순서는 선택한 우선순위입니다.

1. **보안 기록 보기와 AI 설명** — 15·18단계 `renderEvents`·`renderExplanation`. 기록의 종류·업무 앱·접속 상태 걸러 보기와 상세 확인을 다듬고, 기록을 불러오지 못한 상태를 빈 기록으로 오해하지 않게 합니다. AI 설명은 연결·설명 결과를 확인한 경우와 미확인 상태를 구분합니다. 현재 AI·계정 연결은 미확인입니다.
2. **업무 앱 접속 판정과 상태·알림** — 14·16단계 `renderDecision`·`renderStatus`. 앱별 판정, 이유와 시각, 상태·알림을 알아보기 쉽게 다듬습니다. 실제 화면에는 요청 버튼이 없고 아직 요청하지 않아 판정이 없으므로, 예제의 허용·거부 판정을 실제 결과처럼 표시하지 않습니다.
3. **설치 패키지 취약점 조회** — 20단계 `renderVulnerabilities`. `not_configured`를 조회 완료나 취약점 없음으로 오해하지 않도록 상태 표시를 다듬습니다. 현재 조회 대상 프로젝트 설정이 필요합니다.

### 화면 틀·포장 형태와 준비 상태

화면 틀은 **관제 대시보드형**(맨 위 상태 카드 네 개, 아래 추이와 기록)으로, 포장 형태는 **기본 포장**(`npm run package-app` 결과와 바로가기)으로 정했습니다.

다만 현재 시작 틀 `0.2.14`의 `package.json`에는 `package-app` 명령이 없습니다. 2·3일차에 제공될 「내 PC 상태」와 `student/appearance.json` 지원도 없습니다. 강사님 제공 파일 업데이트가 필요하지만 아직 요청 전입니다. 따라서 이 항목들은 **준비 대기**이며, 포장 실행이나 바로가기 생성이 성공했다고 기록하지 않습니다.
